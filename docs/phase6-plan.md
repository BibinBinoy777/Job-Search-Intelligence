# Phase 6 repository audit and implementation plan

The current app is React 19/TypeScript/Vite with TanStack Query, FastAPI, SQLAlchemy/PostgreSQL and Alembic `0005_resumes`. Phases 1–5 have 187 backend, 36 frontend and six isolated browser tests. No Git checkout exists; a full source manifest and read-only database row hashes were captured before Phase 6 changes. Tests remain guarded to separate `_test`/`_browser` databases.

Reuse `matching/skills.py`, `candidate.py`, `requirements.py`, `representations.py`, `ingestion/freshness.py`, profile/preferences and owned resume proposal references. Career analysis must neither write candidate records nor create matching assessments. Unconfirmed extraction is distinct from confirmed/recorded profile inputs. The current schema already supplies every needed identifier; no additional candidate system or migration is needed.

Implement `modules/career/` with typed filters/responses, candidate evidence, scoped read-only retrieval, reusable deterministic analysis and a small reviewed provider-resource catalog. One authenticated dashboard request computes all sections consistently using one as-of time; no persistent cache or separate per-card computation. Recompute on filters/profile changes and refresh on focus/mount. Preserve all existing matching engine files and ranking semantics.

Scope listings with existing availability rules plus explicit status/deadline exclusions, source/location/publication filters. Separate the larger role-discovery population from target-role gap denominators. Count distinct conservative exact-content groups once and expose excluded duplicate counts. Limit bounded local analysis transparently; never label a truncated population as the full market. Exclude incidental skill mentions from frequencies. Expose source requirement spans and original job IDs without raw private resume text.

The dashboard follows the existing design: your skills → gaps → roles → staged transitions → skill-linked learning → sample evidence. Actual listing titles and shared requirements support exploratory roles; no title-only suitability, invented timelines, salary or hiring probabilities. Resources verified against provider pages have identity/date/source evidence; other skills receive clearly unverified learning directions without fabricated course URLs. Store verification snapshots as source JSON, not candidate data.

Add focused backend/property/authorization/update tests, component states/interactions and real browser evidence-to-job/role/path/learning/profile journeys with mobile checks. Run all existing regressions, lint/type/build/schema/advisory checks, database preservation and final source/package review. Update architecture/API/README/methodology/limitations and stop after Phase 6 locally; no Git publication, deployment or later phases.
