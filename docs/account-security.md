# Account security and privacy

Existing Argon2 passwords, hashed opaque-cookie sessions, origin checks and candidate ownership remain. The authenticated account page lists own session expiry with noncredential opaque references. Revoke-all includes the current session. Password change requires the current password and a 12–128 character replacement and revokes all sessions/recovery credentials.

Recovery requests have uniform responses for existing/missing accounts and bounded per-process throttling. Recovery credentials never appear in HTTP responses/logs. Email recovery delivery is not configured. In development/test only, a trusted local operator can run `python -m app.operations.cli issue-local-recovery --email <registered-email> --output <new-private-file-outside-source>`. Protect the file with account ACLs and remove it after use/expiry. Tokens are unpredictable, stored only as hashes, expire after 20 minutes and are single-use. Issuing again replaces the prior credential. Confirmation uses a POST body and revokes all sessions/tokens. Local issuance is rejected in production. Real delivery/shared abuse limiting require Phase 8B configuration and verification.

Authenticated export returns a private ZIP with versioned account.json, original relationships and owned resume files under UUID names. Password/session digests, other candidates, global jobs/source configuration and unrelated administrative audit records are excluded. SQL-side size/row checks and an overall archive-input cap reject oversized exports. No permanent public URL exists. Derived career responses are not persisted as separate historical records; exported owned inputs preserve their basis. Keep downloaded copies private.

Deletion requires opening the review UI, submitting the current password and typing DELETE MY ACCOUNT. Merely opening review changes nothing. Confirmation durably marks deletion_pending, revokes sessions/tokens and blocks normal access before deleting private objects. Cleanup failure returns 202/pending, never success. Operators retry an already confirmed deletion with `python -m app.operations.cli retry-account-deletion --user-id <uuid>`. Successful cleanup deletes the user and cascades owned profile, applications/history, matches, saves, searches, resumes/extractions, subscriptions, reminders, notifications and delivery records. Shared vacancies/source history remain. Obsolete reminder tasks cancel safely; shared event tasks cannot recreate a missing profile.

Generic audit action/resource UUID/time records remain with user FK cleared; they contain no resume/profile contents. These remain pseudonymous operational metadata. No legal retention period is asserted. Backups/downloaded exports have separate retention and are not erased by account deletion. Expired sessions are invalid and cleaned on new session creation; expired recovery rows are unusable and need operator maintenance. Notification/application history and failed extraction originals are not silently expired. Temporary parser directories are cleaned normally; hard-crash orphans require controlled maintenance. Backup pruning is configurable and previewed; log/audit retention remains an explicit operator policy.
