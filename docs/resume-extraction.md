# Extraction and evidence contract

PDF and DOCX are implemented. OCR and external AI extraction are not implemented or invoked. The current extractor is `resume-deterministic-1.0`, a local conservative baseline, with no statistical confidence or hiring-quality claims.

PDF uses pypdf in strict mode, checks encryption, active catalog/page actions, attachments and supported dangerous annotations, and retains one text segment per non-empty page. Image-only PDFs return `ocr_required` when image objects are detected; empty selectable-text output otherwise returns `empty_text`. OCR detection is heuristic: unusual embedded image/form layouts can return the generic no-text result. Neither result claims OCR occurred. Reading order, columns, fonts and visual layout are not reconstructed reliably. pypdf is not an OCR engine; see its [official extraction limitations](https://pypdf.readthedocs.io/en/stable/user/extract-text.html).

DOCX uses bounded ZIP reading and defusedxml with DTDs/entities/external entity access forbidden. Main document paragraphs, including table-cell paragraphs, and supported headers/footers are read in part order. Deleted text and field instructions are omitted. Hyperlinks are never fetched; unsupported external relationships are rejected. No DOCX page numbers are invented. Complex text boxes, drawings, tracked changes, cross-part ordering and nested layouts can be omitted. See [defusedxml project documentation](https://pypi.org/project/defusedxml/) for XML threat background.

Recognized headings identify skills, experience, education, certifications, projects, summary and languages. Skills are suggested only in explicit skill, experience or project sections; recognized negative mentions are excluded. No new alias taxonomy is introduced. A mention remains a reviewable suggestion, not a verified professional qualification. Deterministic parsing can miss unusual headings and misinterpret atypical layouts; the candidate inspects every proposal and can reject or edit it.

Employment supports `Title | Employer | dates | responsibilities` and `Title at Employer | dates`. Missing fields and narrative achievements are not invented. Exact ISO days can become dates; year/month-only ranges remain raw `date_text` with null dates. Present/current/ongoing text creates no end date. Education supports `Qualification | Institution | dates | status`; missing completion remains unknown, negated completion stays unknown, and expected/pursuing text remains in progress. A date or degree mention alone never establishes graduation. Certification metadata retains issuer, issue/expiry text, credential reference when supplied and `not_verified` validity. Projects retain exact descriptions/responsibilities/technology mentions. Language proposals require a recognized language prefix. Unsupported categories can be entered manually rather than invented.

Each proposal stores immutable original values and `(segment_id, start, end, section)` pointing into the extraction's stored text. API excerpts are reconstructed directly with `segment.text[start:end]` and include exact version ID, extractor version and PDF page or DOCX part. Tests compare every proposal's excerpt with its persisted source segment in both formats; edited values never mutate that source span. Deduplication may retain the first occurrence rather than every occurrence of a repeated fact. Evidence is exact extracted text, not a claim that a PDF's visual reading order or underlying qualification is independently verified.

Default bounds: 5 MiB upload, 50 pages for PDF, 120,000 extracted characters, 1,500 nonempty text segments, 100 proposals; DOCX allows at most 200 ZIP members, 20 MiB total expansion and 100:1 per-member compression ratio. PDF decoded page content is bounded to 8 MiB. A child parser has a 512 MiB memory cap and 15 second wall timeout, with at most two parser children per API process. Limit failures reject processing rather than silently claiming a complete truncated extraction. Large documents should be shortened or re-exported. Timeouts are safe, retryable failures; there is no automatic parsing repair or OCR fallback.
